# PHANTOM 全面代码审查与优化报告

## 1. 结论

当前版本已经从“以研究数据为中心的牌桌”重构为“辅助智能体优先、实战沙盘验证”的
本地 Demo。评委进入首页先理解规则校验、候选比较、透明解释和跨局学习，再选择亲自验证
或观看自动推演。完整牌型中文识别、倍率和春天结算继续作为建议可信度的规则基础。

## 2. 已发现并修复的问题

### P0：影响可用性或安全

| 问题 | 影响 | 修改 |
|---|---|---|
| 真人手牌曾继承观战模式的禁止点击样式 | 玩家无法选牌 | 将交互态与观战态样式分离，并完成实际点击出牌验证 |
| 任意网页都可以尝试连接本地 WebSocket | 恶意网页可能消耗本地推断资源 | 只接受 `localhost:5173` 与 `127.0.0.1:5173`，其他来源以 1008 拒绝 |
| 真人动作载荷没有显式大小限制 | 超大数组可能造成无意义的解析与排序 | 限制为最多 20 张、每个牌面标识最多 2 个字符，并继续使用真实合法动作表校验 |
| 回放读取没有文件与事件上限 | 损坏或异常文件可能占用过多内存 | 限制单回放 5 MB、1000 个事件、单事件 1 MB |
| 损坏的行为画像会阻断真人开局 | 本地文件异常导致模式不可用 | 严格验证字段与非负计数，异常时无损回退到全新学习画像 |
| 后端异常文本直接发送给界面 | 可能暴露本地路径或内部实现 | 对玩家只返回中文恢复建议，详细异常留在本地日志 |
| 真人回合覆盖了上一手动作 | 玩家不知道当前需要压什么牌 | 真实状态常驻上一手玩家、牌面、牌型及是否拥有牌权 |
| 牌型界面只认识少数基础组合 | 三带一、三带二会显示成“若干张组合”，造成规则缺失错觉 | 新增完整中文牌型分类器，并用底层生成动作做一致性抽样验证 |

### P1：玩法和用户体验

| 问题 | 影响 | 修改 |
|---|---|---|
| 首页以“你是地主、先出完即胜”为首要命题 | 评委容易把作品误判为普通斗地主游戏 | 首屏改为“可解释斗地主辅助智能体”，明确牌局只是验证环境，主入口改为“进入辅助体演示” |
| 研究面板抢占游戏主视觉 | 普通玩家一进来先看到术语而不是玩法 | 牌桌成为主画面，侧栏只保留“现在做什么、建议、本局形势”，高级数据折叠为策略实验室 |
| 推荐动作只显示文本 | 重叠手牌下需要玩家自己寻找多张同点数牌 | 增加“采用建议”，按牌面出现次数准确映射到实体手牌，仍需玩家确认 |
| 操作反馈只有“合法/不合法” | 不利于理解牌型 | 覆盖三带一、三带二、顺子、连对、三类飞机、四带二、炸弹和王炸，并区分非法组合与压不过 |
| 每局使用同一副牌 | 真人模式重复体验弱 | 保留固定种子供核心演示，同时为真人模式增加确定性的新牌种子序列 |
| 移动端层级混乱 | 牌桌、席位和分析内容相互争夺空间 | 390px 下先完整呈现牌桌和出牌操作，再按顺序展示助手内容，无横向滚动 |
| 缺少倍率与春天结算 | 即使出炸弹或形成春天，终局反馈也没有规则意义 | 按炸弹/王炸次数翻倍，识别春天和反春天，并展示阵营分值 |
| 异常和终局缺少明确下一步 | 玩家不知道如何恢复或继续 | 增加“重新连接”“再来一局”“重新观看”直接操作 |
| 关键文字过小、对比不足 | 长时间观察困难 | 提升核心控件、状态、任务、候选与指标字号和灰阶对比；装饰性元数据保持克制 |
| 技术来源标识大量英文外露 | 破坏中文沉浸感 | 牌桌改为“你的操作 / 认知策略 / 基础策略”，规则来源改为中文；仅保留品牌和牌面英文 |
| 两名电脑席位一上一直，破坏三人对战空间关系 | 玩家不易建立上家、下家和行动方向 | 电脑上家固定在左、电脑下家固定在右，顶部仅显示局况、回合任务与地主底牌 |
| 对手牌背固定显示六张 | 即使数字正确也会让人误以为余牌是假数据 | 数字直接绑定后端剩余手牌，缩略牌堆按余牌数量分段减少，并增加逐手守恒测试 |
| 行动者只靠提示文字辨认 | 节奏稍快时无法看清谁出了什么 | 手牌按左、右、下三种真实方向飞入中央，行动席发光并出现身份印章；“不出”也有独立视觉反馈 |
| 选中牌被置于所有邻牌之上 | 抬起的牌遮挡右侧牌面并抢走点击，连续选牌困难 | 牌面装饰层不再接收指针，选中牌保持正常扇形层级，邻牌始终拥有独立命中区域 |
| 只能逐张点击选牌 | 顺子、连对和飞机需要大量重复操作 | 增加跨鼠标、触控笔和触屏的连续拖选，沿路径预览，松开统一确认，并支持批量取消 |
| 席位仅使用文字印章 | 角色辨识和情感连接不足 | 重绘三张统一可爱国风卡通头像，按地主、上家、下家形成红黑、靛蓝、茶褐配色区分 |
| 回合提示动画覆盖 CSS 居中位移 | 窄屏提示框向右偏移并截断说明 | 将水平居中纳入动画变换本身，桌面和 390px 手机均保持准确居中 |

### P1：性能和稳定性

| 问题 | 影响 | 修改 |
|---|---|---|
| 一次认知决策重复执行对手信念估计 | 每次多遍历约 1024 个观察者粒子视图 | 反事实推演复用已计算的完整前置信念，公开事件中移除内部缓存字段 |
| 断线固定间隔无限重连 | 后端长期离线时持续制造连接 | 改为最多 4 次、0.7/1.4/2.8/5.6 秒指数退避，随后给出手动重连入口 |
| 前端只检查 `mode` 和 `source` | 错误协议可能进入 UI | 增加 JSON 解析保护和 `phantom.game.v1` 协议校验 |
| 一键启动只判断端口占用 | 可能误连其他程序或旧版本 | 同时验证前端页面身份和后端完整能力状态，不兼容时明确终止 |
| 真人局动作停顿发生在发送之前 | 最后一名农民动作会被下一次真人提示立刻覆盖，看起来像“跳手” | 把 1.7 秒阅读停顿统一放到每个动作发送之后，逐帧确认 1→2→3→4 手连续可见 |
| 网页首次固定使用展示种子 | 刷新后总是同一副牌，用户会误以为发牌是预设的 | 真人局与示范局改用浏览器安全随机种子，固定种子只服务测试与回放 |
| 行为画像只在终局保存且没有展示 | 中途退出丢失学习，用户也感受不到 AI 成长 | 每次选择立即持久化，增加四阶段成长、实时进度、洞察文本和个性化强度 |
| 行为画像不改变农民行动 | “越下越聪明”停留在文案层 | 第二局起在 DouZero 前五候选和严格价值损失范围内进行玩家风格自适应择优 |

## 3. 玩法设计评价

### 当前核心循环

1. 首页理解产品：这是辅助智能体，牌局是可操作的验证沙盘，玩家保留最终决定权。
2. 查看桌面上一手牌型与出牌玩家。
3. 选择相同牌型中更大的组合，或在允许时选择不出。
4. 需要帮助时采用智能建议，最终仍由玩家确认。
5. 炸弹、王炸与春天改变倍数，清空手牌后结算。
6. 成长条随玩家每次选择推进，终局说明 AI 学到了什么以及下一局会怎样调整。
7. 感兴趣的玩家再展开策略实验室，查看候选和对手信念。

这个循环把“智能体如何帮助决策”放在第一层，把完整牌局作为可信度验证方式，并将
“对手以为我有什么”等研究内容保留为第二层差异化能力。

### 当前关卡结构

- **作品介绍**：一句话说明辅助智能体价值，并展示“读取局面 → 比较方案 → 交还决定”。
- **实战辅助**：玩家控制地主，在真实牌局中检查校验、建议与解释是否一致。
- **自动推演**：不需要操作即可观察辅助体的完整判断过程。
- **稳定回放**：在后端推断不可用或需要讲解时还原完整事件。

### 后续版本建议

这些内容需要新的规则与数值测试，不宜在本轮稳定性改造中仓促加入：

1. **叫分与抢地主阶段**：补齐完整斗地主赛前决策，让身份选择本身成为第一层心理博弈。
2. **三档挑战**：教学局显示建议；标准局只显示候选；专家局隐藏真实状态，终局再揭示。
3. **章节式认知任务**：藏锋、诱导炸弹、控制权交换、残局收割，每章使用独立验收种子。
4. **局后复盘页**：按关键转折点而非逐手流水展示“如果采用另一动作会发生什么”。
5. **完整赛制计分**：在现有炸弹、王炸和春天倍率上接入叫分基础倍数与连续对局积分。
6. **长期学习边界**：为行为画像提供查看、重置和禁用入口，再考虑更长周期的个性化。

## 4. 代码结构评价

### 做得较好

- 上游 DouZero 保持隔离，没有为了方便修改第三方核心。
- 基础策略、认知、状态机、画像、评估、录像、API 和 UI 分层明确。
- 所有真实动作最终仍由 DouZero 环境合法动作表约束。
- 认知失败有基础动作回退，安全门是硬约束而非仅界面提示。
- 固定种子、来源字段、逐手录像和指标使结果可复现、可审计。

### 仍需关注

- 当前 FastAPI 服务是单机 Demo 形态；若转为多人服务，需要会话隔离、并发画像合并、配额和鉴权。
- 对手信念仍是 CPU 上逐粒子计算；更高粒子数应改为张量批处理或独立工作线程。
- React 事件类型由手写类型维护；协议稳定后应从共享 JSON Schema 自动生成前后端类型。
- 回放目录目前只列出记录，没有管理界面；如加入删除功能，必须提供确认和恢复策略。
- 基础模型值不是校准胜率，界面应继续称为“基础价值”，不能改称“胜率”。

## 5. 本轮主要文件修改

- `frontend/components/phantom/game-lobby.tsx`：游戏原生首页与唯一主入口。
- `frontend/components/phantom/rules-dialog.tsx`：完整牌型、比较、倍率和胜负说明。
- `frontend/components/phantom/dou-dizhu-rules.ts`：即时中文牌型识别与操作反馈。
- `frontend/components/phantom/phantom-stage.tsx`：游戏/示范主线、规则入口与新牌局能力。
- `frontend/components/phantom/real-game-table.tsx`：上一手目标、三方向出牌动画、行动者印章、完整牌型反馈、建议选牌和结算。
- `frontend/components/phantom/opponent-seat.tsx`：左右对称电脑席位、实时余牌、动态牌堆与行动反馈。
- `frontend/public/avatars/`：三张原创角色头像及面向网页的 WebP 轻量化素材。
- `frontend/components/phantom/real-policy-panel.tsx`：面向普通玩家的助手与可选策略实验室。
- `frontend/components/phantom/use-real-game.ts`：协议校验、有限重连、新牌种子。
- `frontend/app/globals.css`：可读性、移动导航、引导、任务与反馈视觉系统。
- `phantom/cognition/counterfactual.py` 与 `phantom/bridge/session.py`：复用前置信念，减少重复推断。
- `phantom/game/rules.py`：不修改第三方引擎的完整中文牌型分类、倍率与春天数据支撑。
- `phantom/api/server.py`：来源限制、输入上限和错误脱敏。
- `phantom/telemetry/replay.py`：回放资源上限。
- `phantom/opponent/profile.py`：损坏数据安全回退、四阶段成长、实时洞察与自适应强度。

## 6. 验收标准

- 全部 Python 自动测试通过。
- 前端代码检查与生产构建通过。
- 1920×1080 无页面溢出，核心任务与操作在首屏可见。
- 390px 手机宽度无横向溢出，主操作在牌桌之后、分析内容之前。
- 两名电脑玩家始终位于左右两侧；对手出牌后数字和牌堆同步减少，行动方向可被一眼识别。
- 真人模式能查看完整规则、采用建议、识别具体牌型并确认合法出牌。
- 单击可选一张；横向拖过连续牌后松开可批量选择；选中后左右相邻牌仍可直接点击。
- 三带一、三带二及全部底层生成牌型均有准确中文名称。
- 非本地网页来源无法连接牌局 WebSocket。
- 超大真人动作、损坏画像和超大回放都能安全失败而不影响下一局。
- 浏览器控制台无错误或警告。
